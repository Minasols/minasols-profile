# minasol's profile

A personal about-me page heavily inspired by MySpace profiles circa 2006-2010:
table-based layout, colored module headers, Top 8 friends, a comments section,
a music player module, and a scrolling marquee banner. Built with plain HTML,
CSS, and vanilla JavaScript — no build step, no frameworks, no dependencies.

## File structure

```
minasols-profile/
├── index.html                  the page skeleton (layout only, no content)
├── assets/
│   ├── css/
│   │   └── style.css           all visual styling + theme color variables
│   ├── js/
│   │   ├── config.js           <-- YOUR CONTENT GOES HERE
│   │   └── render.js           reads config.js and builds the page (layout logic only)
│   └── img/
│       ├── profile-placeholder.svg
│       └── friend-placeholder.svg
└── README.md
```

The split matters: **content lives in `config.js`, structure lives in
`index.html`, layout logic lives in `render.js`, and appearance lives in
`style.css`.** You should be able to make this page fully yours by editing
only `config.js` and swapping images, without touching HTML, CSS, or the
render script at all.

## Adding real icons (logo, online-now, contact icons)

Nine spots on the page are placeholders waiting for real icon images: the
navbar logo, the "Online Now!" dot, and the 8 icons in the Contacting box.
Each currently renders as a small dashed-border tag (like `[LOGO]`) so it's
obvious where an image belongs.

**Step 1:** Drop your image files into `assets/img/icons/` using these exact
filenames (see `assets/img/icons/README.txt` for the same list):

```
logo.png, online-now.png, send-message.png, add-to-friends.png,
im-call.png, add-to-group.png, forward-to-friend.png,
add-to-favorites.png, block-user.png, rank-user.png
```

**Step 2:** Replace the placeholder markup with a real `<img>` tag. Open
`index.html` and swap each one:

For the **logo** (in the row-1 navbar), replace:
```html
<div id="logo-slot" class="icon-slot" title="Place logo image at assets/img/icons/logo.png">
  <span class="icon-slot-label">[LOGO]</span>
</div>
```
with:
```html
<div id="logo-slot">
  <img src="assets/img/icons/logo.png" alt="logo">
</div>
```

For the **online-now icon**, replace:
```html
<span class="icon-slot online-icon-slot" title="Place icon at assets/img/icons/online-now.png">
  <span class="icon-slot-label">●</span>
</span>
```
with:
```html
<img src="assets/img/icons/online-now.png" alt="" style="width:14px;height:14px;">
```

For the **8 Contacting-box icons**, open `assets/js/render.js` and find the
`renderContact` function. Each icon is generated by this helper:
```js
function contactIconSlot(iconFileName) {
  return `<span class="icon-slot contact-icon-slot" title="Place icon at assets/img/icons/${iconFileName}"><span class="icon-slot-label">&#9679;</span></span>`;
}
```
Replace its return line with:
```js
  return `<img src="assets/img/icons/${iconFileName}" alt="" style="width:16px;height:16px;">`;
```
This one change updates all 8 contact icons at once, since they all call
this same helper with different filenames.

You don't have to do all nine at once — do them one at a time as you get
assets, and the rest will keep showing their placeholder tags until you get
to them.

## Customizing your content

Open `assets/js/config.js`. Everything in there is one JavaScript object,
`PROFILE_CONFIG`. Edit the values (never the property names on the left of
each `:`) to change:

- `displayName`, `tagline`, `status` (`"online"` or `"offline"`)
- `profilePicture` — path to your photo (see "Adding your own images" below)
- `bannerText` — the scrolling marquee message at the top
- `generalInfo` — any label/value pairs you want (mood, age, location, etc.)
- `contact` — email/instagram/github/discord; leave any as `""` to hide it
- `aboutMe` / `whoIdLikeToMeet` — arrays of strings, one paragraph each
- `interests` — any label/value pairs
- `music.tracks` — playlist entries; add a real audio file path to `src` to
  enable the inline player, or leave `src: ""` to just display the tracklist
- `topFriends` — up to 8 entries with `name`, `pic`, `url`
- `comments` — pre-seeded comments; new ones posted via the on-page form are
  added on top of these for the current visitor's session only (see note
  below on comments)
- `visitorCount` — starting number for the hit counter

Save the file and refresh the page. That's the entire workflow.

## Adding your own images

Drop your image files into `assets/img/` (e.g. `assets/img/me.jpg`), then
point to them from `config.js`:

```js
profilePicture: "assets/img/me.jpg",
```

Same pattern for friend thumbnails (`pic` field) — square images work best
since they're cropped to a square automatically.

## Customizing the color scheme / layout style

Open `assets/css/style.css` and look at the `:root { ... }` block at the very
top. Every color on the page is a CSS variable defined there:

```css
--module-header-bg: #ff00cc;    /* hot pink */
--module-header-bg2: #9900ff;   /* purple, gradient partner for headers */
--accent2: #00e0ff;             /* cyan, used for outlines/highlights */
--accent3: #ffe600;             /* yellow, used for borders/dividers */
```

Change these hex values to reskin the entire site — every module header,
border, and highlight pulls from this same palette automatically. Some
starting-point alternate palettes if you want a different vibe than
hot-pink-and-purple:

- **Emo/scene (black + red):** `--module-header-bg: #000000; --module-header-bg2: #cc0000; --accent2: #ffffff; --accent3: #ff3333;`
- **Y2K cyber (black + acid green):** `--module-header-bg: #000000; --module-header-bg2: #003300; --accent2: #00ff41; --accent3: #ffffff;`
- **Pastel scene girl (baby blue + white):** `--module-header-bg: #a3d5ff; --module-header-bg2: #ffffff; --accent2: #ffb3d9; --accent3: #fff9a3;`

`--font-header` (currently Comic Sans MS) and `--font-display` (currently
Impact, used only for your name) are also swappable there.

## The music player

The `<audio>` element only appears if at least one track in
`config.js` has a real `src` path. Browsers generally block autoplaying
audio with sound, so this is a real, silent-by-default player rather than
the old auto-blaring embed — the visitor presses play. If you don't provide
any `src`, the tracklist still displays, just without playback controls,
which is a reasonable way to list favorite songs without hosting audio
files.

Keep any audio files you add reasonably small and be mindful of copyright:
GitHub Pages is a public host, so only upload audio you have the rights to
publish (original recordings, royalty-free tracks, or your own voice/music).

## About the comment form

The on-page comment form is functional in the browser (it appends a new
comment to the visible list) but **does not persist anywhere** — it resets
for every visitor and every page reload, since this is a static site with no
backend or database. It's there for show/authenticity. If you want real
persistent comments, you'd need to wire it up to a third-party comments
service (e.g. giscus, which uses GitHub Discussions) or a small backend,
which is out of scope for a plain-HTML/CSS site but worth knowing going in.

Similarly, the visitor counter increments once per browser session using
`localStorage`, purely for the nostalgic effect — it's per-visitor local
state, not a real shared global counter.

## Deploying to GitHub Pages

1. Create the repository on GitHub named `minasols-profile` (or push this
   folder's contents into it if you've already created it).
2. Push all these files to the `main` branch:
   ```bash
   git init
   git add .
   git commit -m "initial commit"
   git branch -M main
   git remote add origin https://github.com/<your-username>/minasols-profile.git
   git push -u origin main
   ```
3. On GitHub, go to the repo's **Settings → Pages**.
4. Under **Build and deployment → Source**, choose **Deploy from a branch**.
5. Under **Branch**, choose `main` and folder `/ (root)`, then **Save**.
6. GitHub will publish the site at:
   `https://<your-username>.github.io/minasols-profile/`
   (this can take a minute or two on the first deploy).

No build step, no `gh-pages` branch, no GitHub Actions config needed — this
is a fully static site and root-folder deployment is all it requires.

## Browser support notes

- `<marquee>` is a non-standard, deprecated HTML element, but it is still
  supported by all current major browsers (Chrome, Firefox, Safari, Edge) —
  it's kept alive purely for backward compatibility and nostalgia sites like
  this one. If it's ever removed from browsers in the future, the banner
  text will simply display statically without scrolling, degrading
  gracefully rather than breaking.
- The layout uses an actual HTML `<table>` for the two-column structure, on
  purpose, both for period-accuracy and because it's a genuinely simple way
  to do a fixed two-column layout without a CSS framework. It collapses to
  stacked full-width blocks on small screens via a media query.
